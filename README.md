# Xrostr

Autonomous, multi-tenant HRMS for security agencies and shift-based workforces in Singapore and
Indonesia. This repository holds **Phase 0 — foundation**: tenancy with PostgreSQL Row Level
Security, authentication with mandatory 2FA, RBAC, audit log and a transactional outbox.

Architecture and product scope: see the PRD and `docs/adr/`.

## Layout

```
apps/
  api/          NestJS API (modular monolith)
    src/modules/
      identity/   auth, sessions, 2FA, RBAC guard, tenant provisioning
      tenancy/    tenants and legal entities (Superadmin onboarding)
      audit/      tenant audit log reader
    src/shared/   unit of work + tenant context, cipher, audit writer, outbox, HTTP plumbing
  worker/       outbox relay
  web/          Next.js portal (Superadmin and tenant) with a same-origin /api proxy
packages/
  contracts/    Zod request schemas, permissions, roles, shared types
  db/           Drizzle schema with RLS policies, migrations, migrate + seed CLIs
  country-sg/   Country Pack: Singapore
  country-id/   Country Pack: Indonesia
  config/       shared TypeScript config
docs/adr/       architecture decision records
```

Each module has `domain/`, `application/`, `infrastructure/` and `interface/` layers; ESLint
blocks imports that point outward (ADR 0001).

## Getting started

Requires Node 22, pnpm 10 and Docker.

```bash
pnpm install
cp .env.example .env        # then set JWT_SECRET and FIELD_ENCRYPTION_KEY
pnpm db:up                  # PostgreSQL 17 on 127.0.0.1:5440
pnpm build
pnpm db:migrate             # creates the xrostr_app role, applies migrations and grants
pnpm db:seed                # first superadmin from SEED_SUPERADMIN_*
./start.sh                           # API 127.0.0.1:8016, portal 127.0.0.1:8015
```

## Mobile app (PWA) and push notifications

The portal is an installable PWA (manifest, icons in `apps/web/public/icons/`, service worker
`apps/web/public/sw.js`). Tenant users install it and turn on notifications from **Akun**; on
iPhone, Web Push works only after _Add to Home Screen_.

Notifications are stored in the user's inbox (`notifications`) and queued through the outbox;
the worker delivers them with Web Push and drops subscriptions the push service reports as
gone. Signing out detaches the device, so a shared phone never receives the previous user's
notifications. Set `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` and `VAPID_SUBJECT` in `.env`;
without them notifications stay in the inbox only.

The theme is dark by default; users can switch to light under **Akun** (stored per device).
App icons are generated by `python3 apps/web/scripts/generate-icons.py`.

## Attendance

Each site has a QR poster (Site → _Cetak poster_) pointing to `/checkin?l=<site>&c=<secret>`.
A scan, from the in-app scanner or the phone camera, records a check-in or check-out only with
the site's current code, a GPS position inside the site's radius (reported accuracy counts for at
most 50 m), and a published shift whose window is open (2 h before start until 4 h after end).
Rotating the code voids printed posters. The worker checks every minute for published shifts
running 15 minutes without a check-in and notifies planners and the officer, once per shift.

## Public access via Cloudflare Tunnel

The web portal listens on `127.0.0.1:8015` and is the only public entry point; it forwards
`/api/*` to the API on `127.0.0.1:8016` and keeps tokens in httpOnly cookies. Nothing listens on
a public interface; the internet reaches the portal through `cloudflared`. Example `~/.cloudflared/config.yml` for a named tunnel:

```yaml
tunnel: xrostr
credentials-file: /home/<user>/.cloudflared/<tunnel-id>.json
ingress:
  - hostname: xrostr.cloud
    service: http://127.0.0.1:8015
  - service: http_status:404
```

```bash
cloudflared tunnel route dns xrostr xrostr.cloud
cloudflared tunnel run xrostr
```

The API trusts proxies on loopback only (`trust proxy = loopback`), so audit logs and rate limits
see the real client IP that cloudflared forwards.

## Running as a service

One command starts or restarts everything, and is safe to run again after every `git pull`:

```bash
./start.sh
```

It starts PostgreSQL, installs dependencies, builds, migrates and seeds the database, installs the
systemd user units from `deploy/systemd/` (pointed at this checkout), restarts `xrostr-api`,
`xrostr-worker` and `xrostr-web`, then checks each one and `https://xrostr.cloud/api/health`.

```bash
journalctl --user -u xrostr-web -u xrostr-api -f               # logs
systemctl --user stop xrostr-web xrostr-api xrostr-worker     # stop
```

## Onboarding flow

1. `POST /platform/auth/login` as the superadmin → session with `stage: "mfa_setup"`.
2. `POST /auth/mfa/setup` → scan `otpauthUrl` in an authenticator app.
3. `POST /auth/mfa/enable` with a code → full session.
4. `POST /platform/tenants` with legal entities (`SG`, `ID`) and the first admin → `inviteToken`.
5. `POST /auth/accept-invite` with the token and a password.
6. `POST /auth/login` with `tenantSlug`, then enrol 2FA the same way (Tenant Admin requires it).
7. `GET /tenant/legal-entities`, `GET /tenant/audit-log`.

All errors are `application/problem+json` (RFC 9457) with a stable `code`.

## Quality gates

```bash
pnpm format:check && pnpm lint
pnpm turbo run build typecheck test   # integration tests start PostgreSQL via Testcontainers
pnpm db:generate                      # must report no schema changes
```

CI (`.github/workflows/ci.yml`) runs the same steps on every push and pull request.

## Changing the schema

Edit `packages/db/src/schema/*`, run `pnpm db:generate`, review the SQL in
`packages/db/migrations/`, commit both. New tenant tables must use `tenantId()` and
`tenantIsolation('<table>')` and call `.enableRLS()`.
